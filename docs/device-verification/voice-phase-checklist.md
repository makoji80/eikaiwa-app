# 音声フェーズ 実機確認手順・チェックリスト

本開発環境（サンドボックス）には iOS/Android の実機・シミュレータが無いため、音声機能（録音・文字起こし・読み上げ）は自動テスト（`apps/api`のvitest）とサーバー単体のcurl疎通のみで確認済みです。**実機での確認はユーザー自身の環境で行ってください。** このドキュメントに結果を記入して残せます。

## 事前準備

1. リポジトリを取得し、依存関係をインストール
   ```bash
   npm install
   ```
2. APIサーバー用の `.env` を用意（[README](../../README.md)参照）し、起動
   ```bash
   npm run dev:api
   ```
3. `apps/mobile/.env` の `EXPO_PUBLIC_API_BASE_URL` を、**実機から到達できるPCのLAN IP**に変更する（`http://localhost:4000` のままだと実機からは繋がらない）。例: `http://192.168.1.23:4000`
   - PCと実機は同一Wi-Fiネットワークに接続すること。
   - PC側のファイアウォールが4000番ポートへの接続を許可しているか確認する。
4. モバイルアプリを起動
   ```bash
   npm run dev:mobile
   ```
5. 実機の Expo Go アプリでQRコードを読み取る。
   - **Expo Goで `expo-audio` 等のネイティブモジュールのエラーが出る場合**は、開発ビルドが必要になる可能性がある。その場合は `npx expo run:ios` / `npx expo run:android`（要Xcode/Android Studio）、または `eas build --profile development` を検討する。
6. アプリ内でユーザー登録（新規登録）してホーム画面に進む。

## 既知の制約（実機確認前に把握しておくこと）

- 押して話す方式のみ。連続対話・割り込み（AI発話中にユーザーが話し始めたら止める）は未実装。
- 音声データはサーバー・端末どちらにも保存しない設計（[decisions/0002](../decisions/0002-voice-phase.md)参照）。
- モック文字起こし（`AI_PROVIDER=mock`、既定）では実際の発話内容は解析されず、固定文言が返る。実際の音声認識精度を確認したい場合は `OPENAI_API_KEY` を設定し `AI_PROVIDER=openai` に変更する必要がある（未検証・要実地確認）。
- 短時間録音の検知はファイルサイズの閾値のみで、実際の無音判定はしていない。
