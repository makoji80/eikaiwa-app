# 英会話アプリ新規開発 実装仕様書 v2.0

作成日：2026-09-25／対象：iOS／Android向け英会話アプリの新規開発／読者：プロダクト責任者、Codex、Claude Code

## 0. 本書の扱いと開発方針

この仕様書を新規アプリの製品要件として扱う。旧Expoアプリを直接改修せず、新しいディレクトリ・独立したGitリポジトリで開発する。旧プロジェクトは参照・比較のため残し、新アプリへデータを自動移行する前提は置かない。既存コードの調査は必須ではない。公開済みユーザーのデータ移行が必要と判明した場合のみ別途移行計画を作る。

開発方式：縦に小さく完成させる。 最初の目標は日本語で言いたいことを話す→英語で発話→AIと会話→保存→後日復習の一巡。追加機能の前に、端末で成立する体験と安全なAPI構成を確認する。設計の未決事項を推測して外部公開しない。

技術の初期案：TypeScript／React Native／ExpoでiOS・Android共通UI、TypeScriptのサーバーAPI、マネージド認証とDB・オブジェクトストレージ。具体的な提供元、SDK、サービスとバージョンは実装着手時に公式資料と料金・対応状況を確認して選定する。OpenAI等のAPIキーはサーバーだけで保持する。ソース管理・開発環境・本番環境を分離する。

## 1. 目的と成功条件

製品約束：自分が本当に言いたいことを英語で言えるようにする。 学習者が日本語で意図を話すと自然な英語の候補が提示され、本人が発話し、AIが意味に応じて英語で応答する。会話中に言えなかった表現は復習され、異なる状況で助けなしに使えるようになる。

中心体験：日本語で意図を入力・録音 → 意味を保った英語を提示 → 本人がその英語を発話 → AIが発話内容に英語で応答 → 会話継続 → 重要表現を保存 → 後日の会話で再利用。翻訳を提示しただけでAIが本人の発話を飛ばして先に応答しない。本人が「聞くだけで続ける」を明示的に選ぶ場合は例外とし、習得判定には含めない。

計測指標：初回の一連フロー完了率、週次の会話継続者数、本人の過去の表現を別文脈で自力使用した割合。目標値は計測基盤と小規模テストの後に定める。発話速度やスコアを根拠なく百分率で表示しない。

## 2. 対象と原則

対象：日本語話者の英会話学習者。初心者から上級者。ビジネス英語と日常会話を本人の話題から作る。iOS／Android。UIの基本言語は日本語、学習会話は英語。

- 音声が使えない環境ではテキストで同じ中心体験を完了できる。
- AIは軽微なミスで会話を止めない。重要な訂正だけを短く示し、会話に戻る。
- 学習支援は段階的に薄くする。レベル表示は初期設定であり、実際の支援量は本人の履歴と設定で調整する。
- 保存する会話、音声、学習履歴と削除設定をユーザーが把握・管理できる。
- LINEログインを採用する場合、認証はマネージド認証基盤に委ねる。秘密鍵・LLMキーをアプリに埋め込まない。

## 5. 中心フローと状態遷移

状態：`idle → listening → transcribing → composing_en → awaiting_user_speech → evaluating_speech → generating_reply → speaking_reply → listening`。テキスト入力時は listening/transcribing を省略。`error` からは直前の入力を残して retry または edit へ戻る。`paused` から復帰できる。ネットワーク送信済みリクエストは idempotency key で二重登録を防ぐ。

1. 日本語を録音または入力し、確定前に転記を編集できる。
2. AIは「意図」「話し方」「本人のレベル」を考慮し、短い英文を原則1件、必要に応じて別案を示す。原文の事実を創作しない。曖昧なら短く確認する。
3. 本人が英文を聞いて発話する。スキップを許すが自力使用として数えない。
4. STT結果を本人に見せ、誤認識なら修正・再録音できる。発話が概ね意図に沿えばAIがその意味への応答を作り、次の質問につなげる。完全一致の暗唱を強制しない。
5. AI応答をテキスト表示・読み上げ。軽微な訂正は後回しにし、意味の誤解を生む場合のみ一文のコーチングを添える。
6. 最大5件の候補を保存提案。ユーザーは編集、非保存、削除を選べる。

中断規則：ユーザーが話し始めたらAI音声を停止可能にする。実装基盤が同時会話を安全に扱えない段階では、押して話す方式で先に出す。割り込み後も直前メッセージが失われないこと。

訂正モード：Conversation＝原則セッション後、Coaching＝繰り返す／意味に影響する誤りのみ会話内、Intensive＝短い練習を増やす。本人が手動選択でき、自動切替時は設定値を超える介入をしない。「5秒リワインド」は名称上の目安で、実際は直近の発話単位（約10～30秒）を対象にして戻る。

## 6. 学習ロジック

### 6.1 My Moments

会話中に本人が言えなかった／助けを求めた／誤りが繰り返された表現を候補化。原文、自然な英語、音声、由来の会話、作成日時、復習状態を保存する。機微な内容は自動保存しない設定を提供し、保存前の確認または確実に取り消せる導線を置く。重複は意味と表現を比較して統合候補を示し、本人の文を勝手に消さない。

復習は翌日以降に別状況の質問として出題。`unknown → recognized → produced_with_help → produced_independently → retained` の観測状態を持つ。状態は回答と支援履歴から更新し、単発成功を「定着」としない。忘れた場合は状態と次回日時を調整。復習間隔は設定可能なルールから始め、実測で改善する。

### 6.2 My English DNA

話題、よく使う表現、詰まりやすい意図、訂正履歴、好みの文章量、支援量、本人が許可した職務・趣味を構造化して使う。人物像や性格を断定しない。MBTI診断を必須にせず、教師の会話スタイルと訂正の好みを設定として扱う。個人プロファイルは編集・削除・無効化できる。

### 6.3 日次ストーリーとAutopilot

前日の本人の話から、1～3分相当の英文を生成し、本人の話とAIが加えた例示を区別する。教材品質：事実保持、レベル適合、自然な口語、論理の流れ、過度な未知語の回避、音声で聞き取りやすい長さ。生成後に自動チェックを通し、不合格なら再生成または編集可能な代替を出す。学習順は Listen → Read → Shadow → Speak without text → Retell。本人が各段階を飛ばせる。

Autopilot は利用可能時間、本人の目標、前回の弱点、復習期限、最近の練習種別を見て次の1タスクを提案。単語／口語表現／リスニング／スピーキングをローテーションする。3分、5分、15分など時間に収まるものを優先し、本人の選択で変更できる。

### 6.4 レベル推定と発展機能

自由会話の後に複数のサンプルを使って暫定レベルと根拠を示す。発音、流暢さ、応答速度、長く話す力、聞き取り、自然さは観測できた項目だけ表示する。聞き取りをテキスト会話だけで判定しない。Real World は割り込み・速さ・曖昧な応答を段階的に導入し、即時停止できる。Future Me は本人の目標に沿う面接や会議の連続シナリオを用意する。外部コンテンツは入力権限と利用条件が明確な素材に限る。

## 7. データモデル（論理モデル）

すべてのユーザーデータは user_id で分離。IDはUUID等、時間はUTC保存・表示時にローカル化。削除と保持期限は設定と運用ポリシーを実装前に確定。

| エンティティ | 主なフィールド | 制約 |
|---|---|---|
| UserProfile | id, locale, level_setting, consent_flags, coaching_mode, created_at | 認証主体との対応を保護 |
| Conversation | id, user_id, topic, status, started_at, ended_at | 所有者のみ参照 |
| Message | id, conversation_id, role, language, text, source_type, created_at | 順序と再試行IDを保持 |
| SpeechAsset | id, message_id, storage_ref, duration, retention_until | 既定の保存範囲を明示、削除連動 |
| TranslationAttempt | id, source_message_id, source_text, suggested_text, selected_text, user_spoke, confidence | 提案と本人発話を区別 |
| EnglishMoment | id, user_id, source_message_id, jp_intent, en_expression, state, next_review_at, archived_at | 編集・削除・重複管理 |
| ReviewAttempt | id, moment_id, prompt, answer, assistance_level, outcome, reviewed_at | 他文脈での再現を追跡 |
| LearningProfile | user_id, topics, preferences, observed_patterns, updated_at | 推定の根拠と編集履歴 |
| DailyLesson | id, user_id, source_conversation_ids, text, status, created_at | 出典と生成を区別 |
| Assessment | id, user_id, dimension, evidence_refs, estimate, confidence, assessed_at | 未測定をゼロ点にしない |
| UsageEvent | id, user_id, feature, units, estimated_cost, occurred_at | 運用集計は最小限 |

物理スキーマは採用したDBに合わせて正規化してよいが、この区別を失わない。生音声は保存が必要な場合に限る。秘密・トークンはこれらのテーブルに平文で置かない。

## 8. API・AI契約

Phase 0で選定したバックエンドでAPIを提供する。クライアントからモデル提供者へ秘密鍵で直接アクセスしない。認証済みリクエストをバックエンドが検証し、利用制限とログ最小化を行う。下記は機能上の契約であり、パス・モデル名・SDKはPhase 0の技術選定後に決める。

| 操作 | 入力 | 出力 | 障害時 |
|---|---|---|---|
| transcribe | audio または upload_ref, locale, request_id | transcript, language, confidence_if_available | 原文編集・再録音 |
| compose | jp_intent, level, context_summary, request_id | english, alternatives?, clarification?, rationale_short? | 入力保持・再試行 |
| reply | conversation_id, spoken_text, selected_translation?, recent_history, style, request_id | reply_text, follow_up?, correction?, moment_candidates[] | 同じ発話で再試行 |
| synthesize | text, voice_preference, request_id | playable_audio_ref または stream | テキストのみ継続 |
| save_moment | expression, source_ref?, consent, request_id | moment_id, revision | 保存失敗を明示 |
| review | moment_id, prompt_context, answer, assistance | feedback, next_review_at, state | 結果の重複反映を防止 |
| daily_lesson | duration_target, sources, level, request_id | lesson_id, text, checks | 代替教材／再生成 |

例：`compose` の応答は構造化して検証する。

```json
{
  "english": "We want to build a stronger partnership with Microsoft and bring our solutions to market together.",
  "alternatives": [],
  "clarification": null,
  "rationale_short": "一緒に市場へ出す意図を保った表現です。"
}
```

AI制約：会話履歴は必要な範囲に縮約。ユーザーの事実を捏造しない。翻訳候補と本人が実際に言った文を混同しない。応答に使う文脈は本人の選んだ意図と実発話の両方を確認する。セッション中の訂正を最大1件に絞る設定をサポートする。JSON Schema 等で出力を検証し、不正な応答は安全な再試行へ。モデルへの指示とユーザー発話を区別し、ユーザーの音声に含まれる命令でシステム規則や他ユーザー情報を上書きしない。学習スコアは推測だけで確定しない。

## 9. 音声・認証・非機能

- 音声：録音権限拒否時にテキストへ切替。録音中・送信中・再生中を明確に表示。無音、短すぎる入力、タイムアウト、STT誤認識に再試行導線。再生速度の調整は復習の詳細に配置。端末の通話・バックグラウンド移行で適切に停止・再開。
- 認証：初期のサインイン方式と匿名利用可否を決定する。LINE導入時は公式認可フローとサーバー側のトークン検証を使い、マネージド認証基盤との整合を先に小さく検証。認証と学習データをユーザーIDで確実に結びつけ、ログアウト・アカウント削除に対応。
- セキュリティ：通信暗号化、最小権限、アクセス制御、レート制限、濫用対策、サーバー側の課金上限、ログでの個人情報・鍵のマスキング。音声・会話データの第三者送信範囲を説明し、ポリシーに反映。
- 性能：UI操作は待ち状態を即時表示。STT／生成／TTSごとの遅延を計測し、目標値は端末と回線の試験後に設定。ストリーミングが利用できる場合は逐次表示を検討。失敗時は入力を失わない。
- コスト：ユーザー別・日別の音声時間、入力／出力トークン、TTS利用量、推定費用を記録し、予算上限・通知・機能別の品質調整を設ける。価格や具体的なサービス選定は導入時に確認する。
- アクセシビリティ：字幕、テキスト代替、操作ボタンの読み上げラベル、拡大文字、十分なタップ領域。

## 10. 受入試験

1. 新規ユーザーが日本語で意図を話し、STT転記を直し、英語候補を選んで自分で発話し、AIから意味に沿った英語の応答を得て、次のターンへ進める。
2. 英語候補を表示しただけでは「自分で言えた」と記録されない。発話スキップでも会話は続く。
3. マイク拒否・STT失敗・生成失敗・TTS失敗・通信断のそれぞれで、入力と直前の会話を失わず、テキスト入力や再試行で続けられる。
4. 会話中の軽微な誤りで毎ターン停止しない。コーチング設定に応じて介入し、直後に元の会話へ戻る。
5. 保存表現は復習画面で折りたたみ表示され、個別に再生・編集・削除できる。復習導線は見つけやすく、再生設定は初期表示で主操作を妨げない。
6. 前日の表現が別文脈で問われ、ヒントなしの発話とヒント後の発話を異なる状態として記録する。
7. 他ユーザーの会話・音声・保存表現にアクセスできない。クライアント配布物とログに秘密鍵が含まれない。
8. 1～3分英文は本人の会話の事実を保ち、Listen／Read／Shadow／Speak／Retellで進め、途中から再開できる。
9. アカウント削除・履歴削除・音声保存設定が実際の保存先と派生データに反映される。
10. iOS・Android の実機で主要フローを確認し、実装済みのホーム・会話・復習の退行を検査する。

## 11. 新規プロジェクトの構成と初回の作業

推奨する構成は apps/mobile（Expoアプリ）、apps/api（秘密鍵を保持するサーバー）、packages/contracts（入力・出力型と検証スキーマ）、docs（本仕様と決定記録）を持つ単一リポジトリ。採用するツールと構成が異なる場合は理由を記録する。クライアントからDBへ直接書く構成を採るなら、ユーザー単位のアクセス規則・サーバー側の課金制御を先に実証する。

初回コミットにはREADME、ローカル起動方法、環境変数名だけを示す.env.example、秘密情報を除外する設定、型検査、静的解析、最小限のAPI疎通テストを含める。実際の秘密値はコミットしない。認証前のデモとして固定のサンプル会話を使う場合は本番のAPIと明確に分け、利用者データを保存しない。

### 11.1 実装順序とゲート

1. 基盤：新規リポジトリ・実機起動・開発用サーバー・認証・DB・環境分離・秘密管理。認証が決まるまで、永続化する複数ユーザー向け環境を公開しない。
2. テキスト中心体験：日本語入力→英語候補→本人による英語入力→文脈に沿うAI応答→次ターン。モデルが無応答でも入力を保つ。
3. 音声中心体験：日本語／英語の録音と転記、英文読み上げ、権限拒否と転記編集、再録音。利用する実機ビルド方式を確認する。
4. My Moments：保存・編集・削除・折りたたみ復習と英文再生。他ユーザーとの分離を検証。
5. 別文脈での再使用：復習出題、ヒント履歴、習熟状態更新。
6. 個別化以降：Phase 3～5を順に実装。外部コンテンツは最後に検討。

各ゲートで変更内容、操作手順、受入試験結果、利用量、残る課題を報告。機能未完成のまま課金・ストア公開へ進めない。

### 11.2 開発用の認証と公開時の扱い

開発初期には検証可能な安全なログインを用意する。LINEログインを製品に含めるかは着手前に決め、含めるなら公式認可フロー、マネージド認証基盤との連携、iOS・Androidの復帰動作を先に検証する。匿名モードで保存を認めるならアカウント連携・端末紛失時の挙動を仕様化する。一般公開時にはアカウント・データ削除、プライバシー説明、利用上限、障害監視を完了する。

## 13. 着手前に決めること

1. 新規プロジェクトを作るMacの親フォルダー名とGitの保存先。旧アプリとは別に置く。
2. 開発時からLINEログインを必須にするか。希望がある場合、Phase 0で連携方式を検証する。
3. 自分だけで試す開発版か、一般ユーザー向け有料公開まで進めるか。目標は有料公開として設計するが、最初の実装は開発版から始める。
4. 音声・会話履歴の保存範囲、保存期間、ユーザーによる削除、AI提供者への送信についての方針。
5. 1ユーザーあたりの許容月額原価、想定利用時間、課金方式。決まるまでは費用計測と開発用利用上限を設ける。
6. サービス名、最初に対象とする利用者、ビジネス英語と日常会話の優先度。

未決でもローカルのPhase 0・テキスト試作は進められる。認証、データ保持、費用上限が決まるまでは一般公開しない。技術の詳細は実装時の選定理由・決定記録で補完する。
